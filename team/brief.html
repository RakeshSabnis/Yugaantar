Can It Play DOOM? One map, three jobs

Team TriTokens · Yugaantar DevForge · Track 1 · Project brief · Scores below are from our own local scorer on held-out maps, not leaderboard scores.

USP. The agent builds its own SLAM-style map of the level from nothing but its 64 rays and its own button presses, and that one map does three jobs: it is the spatial memory, it is the input to a learned planner, and it is the source of the curiosity reward that drives exploration. Every action comes from a 1.5M-parameter network that runs in about 1–4 ms on one CPU thread and uses no GPU memory.

1. Rich spatial telemetry: sensory and state representation

We use the wrapper's rays, entity list and vitals and no pixels.

  • Rays: a circular 1D-CNN over the 64 rays (distance, near-ness, hit-type one-hot). Circular padding because the rays wrap around 360°.
  • Entities: a per-entity MLP with a type embedding, then masked attention pooling (two learned queries) plus max pooling, so any number of enemies, pickups and projectiles is handled.
  • Vitals: an MLP over normalised vitals and the agent's own previous action.

The map (submission/slam.py). The observations contain no position and no heading, so the agent estimates both. Heading comes from its own turn actions, using Doom's turn ramp, which we measured (7.03°, 12.30°, then 14.06° per step); it is exact on 99.8% of steps. Position integrates the observed ego-frame velocity with coefficients fitted against true motion (median drift about a quarter of a cell over a whole map). Each step the 64 rays are painted into an occupancy grid. The network reads two ego-centric views of it:

Learned planner. A small convolution block is applied 8 times over the map (value-iteration style), so information spreads across it like a wavefront; its output around the agent feeds a "which way to go" head (16 directions or none), and the button head is conditioned on that prediction. This makes the policy hierarchical: direction first, buttons second. All of it is trained weights; there is no coded path search in the agent. Helper heads (the teacher's goal type; "locked door seen") shape what the GRU keeps.

Not learned in the submitted agent, and permitted by the rules: masking USE / weapon-switch on the step after a press (both are edge-triggered), observation preprocessing (encoding and the map), and a guard that returns a valid action on malformed input or any internal error.

4. Training and exploration pipeline

Maps. The organisers' test maps are UDMF drawn from ASCII grids; we decoded all 13 and wrote a generator in the same format for all four tiers (arenas, multi-room mazes with dead ends, keycard → lock → exit, two-lock gauntlets), each checked for solvability. 1,500 training maps; 180 held-out maps never trained on; 80 more from a different generator as a style check.

Teacher, training only (training/teacher.py). A scripted player with privileged engine state. It only acts on what it has seen so far (a line-of-sight mask and frontier exploration), so its behaviour can be copied from partial observations. It is never imported by submission/.

Stage 1, imitation with DAgger. The network plays, the teacher labels every state the network visits, and the data is aggregated across rounds, so the network learns to recover from its own mistakes. The "which way" head is trained on the direction of the teacher's next waypoint.

Stage 2, reinforcement learning by self-imitation, in the same loop. A value head regresses the discounted return. Where the action the agent itself took did better than the value expected, that action is reinforced (loss −max(R − V, 0) · log π(a|s)); worse-than-expected actions are not reinforced.

Also built and tested, not in the submitted weights. (1) A signed-advantage actor-critic term and a learned curiosity module (random network distillation over the observation and the wide map view, training/rnd.py): stable, but had not beaten the submitted agent on both seed sets by the deadline. (2) Our own recurrent PPO (training/ppo.py): lowered the score in four configurations, the last with a trained critic (860 → 628). The cause: this agent is only stable when trained on a large accumulated pool of games, and PPO trains on small fresh batches. That is why the RL that works here lives inside the pooled loop.

Per tier for the submitted agent (exit rate): combat 33–60%, exploration 42–65%, keycard 51–71%, gauntlet 9–15%. The range is across the three test sets.

Diagnosis-driven work. We ran teacher and agent through all 45 held-out gauntlet maps and logged the stage each run reached. The agent's main failure was specific: in 15 of 45 runs it picked up a key and then never opened a lock, and it kept returning to doors it could not open. That produced the "holding a key" and "tried door" map layers. After them, second locks opened twice as often (4 → 8 of 45).

6. Limitations, stated plainly

  • Gauntlets remain hard: about one run in ten reaches the exit; the teacher manages about six in ten and needs 780 of the 1,050 steps itself.
  • Most of the skill comes from imitation. The RL stage is real and in the weights, but conservative: it tied the imitation-only agent on score, and at equal score we chose the agent that includes it.
  • The agent still wastes time at locked doors it cannot open; the tried-door memory is only partly learned.
  • Our scorer is an estimate of the official one, and scores move by about ±40 between seed sets, so we only trust differences that hold on two seed sets and on maps from a second generator.
  • Map-style risk: if hidden maps are not grid-style, the map memory is less precise. On 80 maps with other cell sizes and random start directions the agent held its score.

With more time: longer runs to get the actor-critic term and the learned curiosity module into the weights, and training on community WADs. Code, training logs of what worked and what did not, and the failure-analysis tool are in the repository (training/, team/WORKLOG.md).
