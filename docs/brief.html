Can It Play DOOM?

Yugaantar 2026 · DevForge Track 1 · Project brief

USP: a neural agent that builds its own map, and is taught before it is left alone

The observations contain no position, no heading and no map. Our agent estimates its own pose from its own actions, draws a map of the level as it explores, and reads that map through a learned planning module. It is trained by imitation of a training-only teacher with DAgger, so it also learns to recover from its own mistakes, with a reinforcement-learning term and a curiosity reward in the same loop. Every action in the submitted agent comes from the trained network; the only other logic is observation preprocessing, action masking and a crash guard, all of which the rules allow.

  • Self-built spatial memory. Heading from the agent's own turn buttons (the engine's turn ramp, measured), position from the velocity in vitals, rays painted into an occupancy grid. No privileged data.
  • It sees what the rays cannot tell it. Locked-door colours and the exit pad are read from the frame and written into the map (page 2). Both were added without retraining and measured on held-out levels.
  • Levels in the organisers' own format. We decoded the template's test maps and generate unlimited solvable levels across all four tiers.

Neural architecture (1.47M parameters, about 6 ms per decision on one CPU thread; limit 40 ms)

64 rays ───────────────► circular 1D CNN ───────────────┐
visible entities ──────► MLP + type embedding, attention ┤
vitals + last action ──► MLP ────────────────────────────┼─► GRU(256) ─► direction head ─► 23 button combinations
own map (fine + wide) ─► 2D CNN + learned planner (x8) ──┘                (+ value and helper heads)
ModuleDesign
RaysCircular 1D CNN over the 64 rays (distance, near-ness, hit type); wraps around 360°.
EntitiesPer-entity MLP with a type embedding, masked attention pooling plus max pooling: any number of enemies and items.
Spatial memorysubmission/slam.py: occupancy grid (free, wall, door, locked door, visited, frontier) in the agent's own odometry frame. The network reads a fine 32×32 egocentric crop and a zoomed-out 16×16 one.
Learned plannerA small convolution applied 8 times over the map, value-iteration style, so "something worth going to is over there" can spread through free space. All weights are trained.
Recurrent coreGRU (256), reset before every map.
HeadsWhich way to go (16 directions or none), then 23 button combinations conditioned on it, a value head, and helper heads (the teacher's goal type; "locked door seen") that force the memory to hold task-relevant facts.

Safety. Inputs are sanitised, act() is guarded so it always returns a valid action, inference runs on CPU with a warm-up pass in __init__. On the official validator: 2 s initialisation, 6 ms median step, exit reached on the test map.

Training and exploration pipeline

  • Map generator (training/mapgen.py): arenas, multi-room mazes with dead ends, key → locked door → exit chains, multi-lock gauntlets; sizes, monsters, key colours and door placement randomised; every level checked for solvability.
  • Teacher, training only (training/teacher.py): frontier exploration, key → lock → exit planning, door handling, combat. It lives outside submission/ and is never imported by the agent.
  • DAgger (training/dagger.py): the network drives, the teacher labels every state it visits, data is aggregated across rounds; later rounds sample tiers 3 and 4 more heavily.
  • Reinforcement-learning term in the same loop: each game is scored with a shaped reward that mirrors the scoring categories; the value head regresses the return and actions that did better than predicted are reinforced (self-imitation).
  • Exploration and curiosity. The frontier layer of the map marks where unexplored space begins, and the reward includes an intrinsic bonus for entering a cell of the agent's own map that it has never stood in.
  • Local scorer and diagnosis (scorer.py, diagnose.py): our estimate of the official categories from privileged state, and a per-tier breakdown of how far each run got and where its time went.

Exit rates are averaged over both sets (384 levels). The local score is our own estimate of the hidden scorer (exit > keys and doors > exploration > kills, minus damage and death, later tiers weighted more), so it is meaningful for comparing versions, not as an absolute; the same agent scores differently on different level sets, and differences under about 60 points are noise. On tier 3 the submitted agent picks up the key in 95% of levels and opens the locked door in 81%; on tier 4 it averages 1.7 keys and 1.4 locked doors per level.

Three additions made from diagnosis, without retraining

A failure analysis on tier 4 (on an earlier checkpoint) showed the teacher finishing 63% of levels and the network 8%, with the network holding the first key but never opening a lock in half of its timed-out runs, and spending 14% of its time at locked doors it had no key for (the teacher: 0%). The rays say "locked door" but not which colour. That led to:

  • Door colours. Each locked door's red, blue or yellow grille is read from the frame, using the depth buffer to keep only pixels on that door. Until the agent holds the matching key, the door is shown to the network as a wall, in its rays and its map; it turns back into a locked door when the key is picked up.
  • Exit pad. The exit is in neither rays nor entities. Its red floor is found in the frame, placed with the depth buffer and shown in the map as frontier, which the network already walks towards. Blood, corpses and fireballs are rejected because an upright sprite has one depth while a pad on the floor spans a range; damage-tinted frames are skipped; and if the agent stands on a "pad" without the level ending, the cue is switched off for that map.
  • Jam mask. Doors are 64 units wide and the player 32, so the agent can catch a door frame. If it has pressed forward for several steps without moving and is not waiting at a door, forward is withheld for a few steps and the network's next choice frees it.

All three are observation preprocessing or action masking from observation fields. The network still makes every decision.

What did not work

  • Stand-alone PPO fine-tuning of the imitation policy lowered the held-out score in every configuration we tried, so it is not part of the submission. The gentler self-imitation term inside the imitation loop trained stably and is what we kept.
  • Painting openable doors into the map as goals lowered tier 3 exits in every test, and an apparent gain from painting keys did not hold up on a second set of levels, so neither is in the submission.
  • Masking USE and fire by hand-written conditions lowered the score on an earlier version (556 → 439) and was dropped.
  • A second, independently built agent with a finer map reached only about 60% of this one's score; this one was kept.

Known limitations

  • Tier 4 is the weak tier (about 18% exits): the agent usually opens one lock, sometimes two, and runs out of time.
  • Map style. Training levels follow the organisers' grid format. On hand-made Freedoom levels the agent explores and fights but reached no exits in our test: switch-operated exits, lifts and switch doors are not handled.
  • The frame cues are tuned to the template's textures (red exit floor, coloured door grilles). With other textures they simply do not fire, and the agent falls back to exploring.
  • The reinforcement-learning term is modest. It matched the imitation-only network's score rather than exceeding it, so the agent is still close to its teacher's ceiling; a stronger RL stage is the natural next step.
