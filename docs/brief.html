Can It Play DOOM?

Yugaantar 2026 · DevForge Track 1 · Project brief

The observations give the agent no position, no heading and no map. Ours builds its own. It tracks its pose from its own actions, draws a map of the level as it explores, and reads that map through a learned planning module. Every action in the submitted agent comes from the trained network.

What sets it apart

  • A self-built spatial memory. Heading from the agent's own turn buttons (the engine's turn ramp, measured), position from the velocity in vitals, rays painted into an occupancy grid. No privileged data.
  • It sees what the rays cannot tell it. Locked-door colours and the exit pad are read from the frame and written into the map (page 2).
  • Imitation and reinforcement learning in one loop, with a curiosity reward for reaching ground it has never stood on.
  • Levels in the organisers' own format. We decoded the template's test maps and generate unlimited solvable levels across all four tiers.

Neural architecture

64 rays ───────────────► circular 1D CNN ───────────────┐
visible entities ──────► MLP + type embedding, attention ┤
vitals + last action ──► MLP ────────────────────────────┼─► GRU(256) ─► direction ─► 23 button combinations
own map (fine + wide) ─► 2D CNN + learned planner (x8) ──┘               (+ value and helper heads)
ModuleDesign
RaysCircular 1D CNN over the 64 rays; wraps around 360°.
EntitiesPer-entity MLP with a type embedding, then attention and max pooling: any number of enemies and items.
Spatial memoryOccupancy grid in the agent's own odometry frame (free, wall, door, locked door, visited, frontier), read as a fine 32×32 egocentric crop and a zoomed-out 16×16 one.
Learned plannerA small convolution applied 8 times over the map, value-iteration style, so "worth going to" spreads through free space. All weights trained.
Memory and headsGRU (256). Heads: which way to go (16 directions), 23 button combinations, value, and helper heads that keep task facts in memory.

Training and exploration pipeline

  • Map generator: arenas, multi-room mazes, key → locked door → exit chains and multi-lock gauntlets, randomised and checked for solvability.
  • Teacher, training only: frontier exploration, key and lock planning, combat. Never imported by the agent.
  • DAgger: the network drives, the teacher labels every state it visits, so it learns to recover from its own mistakes.
  • Reinforcement-learning term: a shaped reward mirroring the scoring categories; the value head regresses the return and actions that beat its prediction are reinforced.
  • Curiosity: an intrinsic reward for entering a cell of its own map for the first time.

Results and what makes it work

It completes the full chain: explore, fight, find the key, unlock, exit

It holds up on levels far larger than the samples

Stress test: 384 generated levels never used in training, with routes of up to 100 cells. The agent picks up the key in 95% of tier 3 levels and opens the locked door in 81%, averages 1.7 keys and 1.4 locked doors per tier 4 level, and finishes about two thirds of the combat and exploration levels. Our local score rose from 1083 to 1198 with the three additions below, on the same network weights.

Three additions that came from diagnosis

We measured where runs broke: an earlier checkpoint held the first key but spent 14% of its time at locked doors it could not open, because the rays say "locked door" but not which colour.

Door colours

Each locked door's red, blue or yellow grille is read from the frame, with the depth buffer keeping only pixels on that door. Until the agent holds the matching key, the door appears as a wall; it turns back into a locked door when the key is picked up.

Exit pad

The exit is in neither rays nor entities. Its red floor is found in the frame, placed with the depth buffer and written into the map as a place to go. Blood and corpses are rejected: an upright sprite has one depth, a pad on the floor spans a range.

Jam recovery

Doors are 64 units wide and the player 32. If the agent pushes forward without moving and is not waiting at a door, forward is withheld for a few steps and the network's next choice frees it.

In all three the network still makes every decision.

Every action is guarded, so a fault can never freeze the player for the rest of a map. Inference runs on CPU. validate.py passes locally and with --docker, reaching the test map's exit in 98 steps.

Where we take it next

  • A stronger RL stage: PPO fine-tuning anchored to the current policy by a KL penalty, to push past the teacher on the longest gauntlets, where time is the constraint.
  • A goal-picking layer on the map, so "take this key to that door" is an explicit learned decision.
  • More map styles: switch-operated exits and lifts, and hand-made levels alongside generated ones.
